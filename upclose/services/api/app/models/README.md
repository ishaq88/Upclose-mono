# Persistence interfaces

`app.models` exports `Base` and the named ORM rows. `create_session_factory(database_url)` returns a SQLAlchemy sessionmaker without opening a connection at import time. The ORM row named `Session` is a buyer session; use `sqlalchemy.orm.Session` for database units of work. UUIDs are generated by Python; database state/default/time constraints remain explicit.

Canonical enums come from `app.contracts.enums`. Database enums use VARCHAR plus CHECK constraints. Pipeline/concept rows additionally represent pending/running work; the ConceptRun wire model describes terminal outcomes.

## Normalization and ownership

- `Finding.zone` and `Finding.part_no` are read-only properties of its persisted `Part` relationship. There is no competing finding-zone column. Load the part relationship before converting detached findings to contracts.
- Every part-scoped run carries `session_id`; composite foreign keys bind concept runs and findings to the same pipeline run, part and session. Finding frame/mask keys refer to same-session artifact rows. `Part.raw_key` refers to an upload belonging to that exact part/session.
- `RevisionFinding` freezes revision membership relationally. `ClaimEvidence` normalizes each finding/frame citation instead of storing unchecked ID arrays in JSON. Query its rows by `claim_id` to produce contract `finding_ids` and `evidence_frame_keys`. Composite foreign keys require the cited finding to belong to the claim's revision and the exact cited frame to belong to that finding. Public claim serializers must omit the frame storage keys.
- `EvidenceSource` holds at most one capture-kit source per session and kind. Raw samples stay in its `data` column; reports reference them only through `data_sha256` and the frozen summary.
- A report's current revision must belong to the same report and session. An entitlement's source purchase must belong to the same report and session. Provider-state verification and refund behavior are service responsibilities; a purchase row alone never establishes verified payment.
- `PipelineRun.config_hashes` is JSONB; both its normalized JSON value and the explicit `config_hash` participate in separate natural uniqueness constraints with `subject_key,input_hash`. Object key ordering and nullable `part_id` cannot evade identity. Services compute hashes from frozen canonical configuration; the database does not assert that a caller-supplied digest matches those bytes.

## Queue and money

`Job.subject_id` is a string because Stripe event IDs are not UUIDs. `session_id` is required except when both `subject_kind=stripe_event` and `stage=billing_event`. This exception permits atomic durable inbox intake before resolving a purchase; queue code must handle these global billing jobs separately from session-deletion fences. Resolving a global event never grants permission to trust browser state or unverified payment metadata. Polymorphic subject existence, stage transitions and conditional lease commits belong to the queue and the corresponding services.

Purchase prices and budget buckets use integer cents. ModelCall `reserved_cost` and `actual_cost` use integer micro-USD, never cents or floats. Actual unknown charges remain nullable; zero is a known zero cost. Multiple pending purchases may have null provider identifiers; non-null Checkout/payment-intent identifiers are unique. Only one open/completing upload may exist per part.

## Migrations and remaining service invariants

Revision `488757f523df` is a static schema snapshot and does not import live model definitions. Cyclic ownership constraints are installed after all tables exist and removed before downgrade. No PostgreSQL extension is needed. The Alembic metadata drift check is part of the real PostgreSQL test suite.

A ready report requires manifest/hash/score/render timestamp; immutable ready evidence, revision snapshot contents, privacy-reviewed derivative hashes, authenticated scopes, verified payments, and removal of private content during deletion are enforced by the corresponding services. JSON payloads must pass the Pydantic contracts before persistence. The request-key CHECK rejects common top-level secret fields but is not a general recursive redactor; route code must only persist its explicitly safe replay DTO, and session creation must never store a bearer-token replay response.

Run `tests/test_models.py` only with `MODEL_TEST_DATABASE_URL` naming PostgreSQL database `upclose_test_*`; it refuses other database names and uses rollback-isolated data. The migration roundtrip intentionally downgrades/recreates schema only in that dedicated test database.

Job.attempt_started_at records the start of the current attempt using the database clock. Running rows require it alongside lease identity; heartbeat deadlines must use this fixed timestamp rather than row creation/update times.
